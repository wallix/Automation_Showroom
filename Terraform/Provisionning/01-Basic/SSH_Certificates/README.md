# SSH Certificates

Instead of copying the public key of every account to the servers, the Bastion can sign the SSH keys of the accounts with a certificate authority (CA) it holds. A server that trusts the CA accepts the accounts of the domain, and each certificate expires on its own. The CA belongs to the domain (`ca_private_key`); the validity of the certificates is set on each account (`certificate_validity`).

## What it creates

```text
global domain "<prefix>.lab" ── CA key generated by the Bastion (ED25519)
  └── account "admin" (certificate_validity = "+30d")
         ├── SSH key generated by the Bastion, signed by the CA of the domain
         └── used on device "<prefix>-srv01", service SSH (port 22)
```

## Run it

The [connection settings](../../README.md#before-you-start) are shared by all the examples.

```bash
cp config.tfvars.example config.tfvars           # set bastion_info_ip, the SSH server, the account
export TF_VAR_bastion_info_token="<API key>"

terraform init
terraform apply -var-file=config.tfvars

terraform output -raw ca_public_key > wallix_ca.pub
```

Then make each SSH server trust the CA (OpenSSH configuration):

```bash
sudo install -m 0644 wallix_ca.pub /etc/ssh/wallix_ca.pub
echo "TrustedUserCAKeys /etc/ssh/wallix_ca.pub" | sudo tee -a /etc/ssh/sshd_config
sudo systemctl reload ssh                        # sshd on RHEL and derivatives
```

To open sessions with the account, authorize a user group on it as in [base](../base/). Clean up with `terraform destroy -var-file=config.tfvars`.

## Things to know

- **The certificate is an SSH user certificate whose principal is the account login** (`admin` here), valid for `certificate_validity` from its signature. `terraform output -raw account_certificate | ssh-keygen -L -f -` shows it.
- **`certificate_validity` needs a leading `+`** (`+30d`, `+12h`): the Bastion answers `A valid validity interval is required (ie +53w20d)` to `30d`. The variable checks it at plan.
- **The CA private key stays on the Bastion.** `ca_private_key` isn't read back, and removing it from the configuration is refused at plan: destroy the domain to drop the CA.
- **A device local domain** (`wallix-bastion_device_localdomain`) takes the same `ca_private_key`, for the accounts of a single server.

## Inputs

| Name | Description | Type | Default | Required |
| ---- | ----------- | ---- | ------- | :------: |
| bastion\_info\_ip | IP address or FQDN of the Bastion. | `string` | n/a | yes |
| bastion\_info\_api\_version | Version of the REST API: v3.12, or v3.8 for an older Bastion. | `string` | `"v3.12"` | no |
| bastion\_info\_insecure\_skip\_verify | Skip the TLS certificate check. Only for a lab Bastion with a self-signed certificate. | `bool` | `false` | no |
| bastion\_info\_password | Password of bastion\_info\_user, when no API key is used. | `string` | `null` | no |
| bastion\_info\_port | HTTPS port of the Bastion REST API. | `number` | `443` | no |
| bastion\_info\_token | API key of bastion\_info\_user. Set this or bastion\_info\_password, preferably with TF\_VAR\_bastion\_info\_token. | `string` | `null` | no |
| bastion\_info\_user | Bastion user that owns the API key (or logs in with bastion\_info\_password). | `string` | `"admin"` | no |
| certificate\_validity | Validity of the certificates signed for the account, with a leading + (+30d, +12h...). | `string` | `"+30d"` | no |
| target\_account\_login | Login of the account used on the SSH server. | `string` | `"admin"` | no |
| target\_host | IP address or FQDN of the SSH server that trusts the certificates of the domain. | `string` | `"192.0.2.10"` | no |

## Outputs

| Name | Description |
| ---- | ----------- |
| account\_certificate | SSH certificate of the account, signed by the CA of the domain (public\_key of the credential). |
| ca\_public\_key | Public key of the CA of the domain, to add to TrustedUserCAKeys on the SSH servers. |
| target | Target that logs in with a certificate (account@domain@device:service). |
