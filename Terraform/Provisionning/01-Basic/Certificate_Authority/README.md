# Certificate Authority

Declares on the Bastion certificate authorities (CA) of your own PKI: an SSH CA by its public key, or an X.509 CA by its certificate. The Bastion stores the public part only, to check certificates issued by that CA. Requires a Bastion with API v3.12 (X.509 CAs in PEM format are new in v3.12).

Not to be confused with [SSH_Certificates](../SSH_Certificates/): there the Bastion is the CA and signs the keys of its accounts; here it trusts a CA it doesn't hold.

## What it creates

```text
tls_private_key (ED25519) ──public key──> certificate authority "<prefix>-ssh"  (ca_type SSH)
tls_self_signed_cert (CA) ──PEM───────> certificate authority "<prefix>-x509" (ca_type X509)
```

The two CAs are generated by Terraform for the demo only. With a real PKI, pass the CA public key or certificate instead, e.g. `ca_certificate = file("corp-ca.pem")`.

## Run it

The [connection settings](../../README.md#before-you-start) are shared by all the examples.

```bash
cp config.tfvars.example config.tfvars           # set bastion_info_ip
export TF_VAR_bastion_info_token="<API key>"

terraform init
terraform apply -var-file=config.tfvars
```

Clean up with `terraform destroy -var-file=config.tfvars`.

## Things to know

- **The demo CA private keys are in the Terraform state** (`tls_private_key`). That's acceptable for a demo only: a real CA key never goes through Terraform.
- **Where a CA is used.** In the REST API, an LDAP or Active Directory authentication domain references a CA (`certificate_authority`, `enable_ca`). Provider 0.17.0 doesn't have these two arguments on `wallix-bastion_authdomain_ldap` and `wallix-bastion_authdomain_ad`, so that link is set outside Terraform.
- **A CA created elsewhere** (web UI, another configuration) can be read with the `wallix-bastion_certificate_authority` data source instead of being managed here.

## Inputs

| Name | Description | Type | Default | Required |
| ---- | ----------- | ---- | ------- | :------: |
| bastion\_info\_ip | IP address or FQDN of the Bastion. | `string` | n/a | yes |
| bastion\_info\_api\_version | Version of the REST API: v3.12, or v3.8 for an older Bastion. | `string` | `"v3.12"` | no |
| bastion\_info\_insecure\_skip\_verify | Skip the TLS certificate check. Only for a lab Bastion with a self-signed certificate. | `bool` | `false` | no |
| bastion\_info\_password | Password of bastion\_info\_user, when no API key is used. | `string` | `null` | no |
| bastion\_info\_port | HTTPS port of the Bastion REST API. | `number` | `443` | no |
| bastion\_info\_token | API key of bastion\_info\_user. Set this or bastion\_info\_password, preferably with TF\_VAR\_bastion\_info\_token. | `string` | `null` | no |
| bastion\_info\_user | Bastion user that owns the API key (or logs in with bastion\_info\_password). | `string` | `"admin"` | no |

## Outputs

| Name | Description |
| ---- | ----------- |
| certificate\_authorities | Certificate authorities created on the Bastion. |
