# UseCase3: one authorization per account of a server

Access is granted account by account: on `Linux_Repositories01`, the admins get `root`, the helpdesk gets `helpdesk`, and both get `repositories`. Each account of each server has its own target group and authorization. Read the [inventory introduction](../README.md) first.

## What the inventory produces

For each account of `vms_inventory`, and its access rule in `user_group_inventory`:

```text
users Helpdesk_User1, Helpdesk_User2 ── user group "Linux_Repositories01_helpdesk" ──┐
                                                                                     ├── authorization "Linux_Repositories01_helpdesk"
target group "Linux_Repositories01_helpdesk" ────────────────────────────────────────┘
  └── helpdesk@local@Linux_Repositories01:SSH
```

The name `<server name>_<account>` ties the three objects together. Each server gets a local domain `local` with its accounts. RDP accounts hold a password (random placeholder: set the real one); SSH accounts hold an ED25519 key generated by the Bastion, whose public key `terraform output account_public_keys` prints for the server's `authorized_keys`.

## Inventory format

```yaml
users_inventory:
  Helpdesk_User1:
    user_name: "Helpdesk_User1"
    profile: "user"
    user_auths: ["local_password", "local_sshkey"]
    ssh_public_key: ""
    # display_name, email, force_change_pwd

user_group_inventory:
  Linux_Repositories01_helpdesk: [Helpdesk_User1, Helpdesk_User2]   # "<server name>_<account>": keys of users_inventory

vms_inventory:
  Linux_Repositories01:
    name: "Linux_Repositories01"
    ip: "192.168.1.12"
    accounts: ["root", "helpdesk", "repositories"]
    service: "SSH"                           # SSH or RDP
    port: 22
```

An access rule must name an existing account, otherwise the plan fails on a missing target group. An account without a rule still gets its target group, unused: `terraform output unused_target_groups` lists them.

## Things to know

- **The number of objects grows with the accounts.** Three servers with seven accounts already make 56 Terraform resources; the model fits when access must be reviewed account by account, not for a large estate with uniform rules ([UseCase2](../UseCase2%20-%20OneAuthorizationPerDepartment/) is lighter).
- **The passwords are in the state** (user passwords, RDP account placeholders). Treat the state as a secret.
