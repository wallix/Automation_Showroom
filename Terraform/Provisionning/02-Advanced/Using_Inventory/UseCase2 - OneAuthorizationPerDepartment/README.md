# UseCase2: one authorization per department

The members of a department share the privileged account of each server of the department (`root`, `administrator`), and the department gets one authorization. Read the [inventory introduction](../README.md) first.

## What the inventory produces

For each department (`IT` here), the same name is used three times:

```text
users User_IT1, User_IT2 ── user group "IT" ──┐
                                              ├── authorization "IT" (RDP, SSH, recorded)
target group "IT" ────────────────────────────┘
  ├── administrator@local@Windows_Common01:RDP     shared account of each server of the department
  ├── administrator@local@Windows_IT01:RDP
  └── root@local@Linux_Common01:SSH
```

Each server gets a local domain `local` holding its account. RDP accounts hold a password (random placeholder: set the real one); SSH accounts hold an ED25519 key generated by the Bastion, whose public key `terraform output account_public_keys` prints for the server's `authorized_keys`.

## Inventory format

```yaml
users_inventory:
  User_IT1:
    user_name: "User_IT1"
    profile: "product_administrator"
    user_auths: ["local_password", "local_sshkey"]
    ssh_public_key: ""
    # display_name, email, force_change_pwd

user_group_inventory:
  IT: [User_IT1, User_IT2]                   # keys of users_inventory

vms_inventory:
  Linux_Common01:
    name: "Linux_Common01"
    ip: "192.168.1.13"
    account: "root"                          # shared account, in the local domain
    service: "SSH"                           # SSH or RDP
    port: 22

target_group_inventory:
  IT: [Windows_Common01, Windows_IT01, Linux_Common01]   # keys of vms_inventory
```

A department needs an entry with the same name in `user_group_inventory` and `target_group_inventory`: the authorization links the two, and the plan fails on a department missing from `target_group_inventory`.

## Things to know

- **Shared accounts, individual traceability.** Several people use `root`, but each session is opened by a named Bastion user and recorded under that name.
- **The passwords are in the state** (user passwords, RDP account placeholders). Treat the state as a secret.
