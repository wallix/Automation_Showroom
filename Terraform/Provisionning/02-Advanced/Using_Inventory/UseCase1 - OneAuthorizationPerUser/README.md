# UseCase1: one authorization per user

Each user gets a personal account on the servers they need, and an authorization of their own. Read the [inventory introduction](../README.md) first.

## What the inventory produces

For each entry of `users_inventory`:

```text
user "Demo01" ── user group "Demo01" ──┐
                                       ├── authorization "Demo01" (RDP, SSH, recorded)
target group "Demo01" ─────────────────┘
  ├── Demo01@Demo@Windows_Common01:RDP     one session account per key of targets
  ├── Demo01@Demo@Windows_Demo01:RDP
  ├── Demo01@Demo@Debian01:SSH
  └── Demo01@Demo@Debian01-APP             application of a VM with a url
```

The account `Demo01` lives in the global domain `Demo` and holds a random password (vault) and an ED25519 key generated by the Bastion. `terraform output account_public_keys` prints the public keys: add them to `~/.ssh/authorized_keys` of the account on the SSH servers.

## Applications

A VM with a `url` gets a standard application, `<VM name>-APP`, that runs AppDriver on the RDS server (`applications.rds_server`) and opens the url. The RDP session on the RDS server uses a dedicated account (`applications.rds_account`); the user's own account is the one the application logs in with. Users with the VM in their `targets` get the application in their target group.

The RDS server needs AppDriver installed at `appdriver_path`. The `-e URL=<url>` parameters are passed to it as is: check them against the AppDriver version installed.

## Inventory format

```yaml
users_inventory:
  demo01:                                   # key: keep it stable
    user_name: "Demo01"
    profile: "product_administrator"        # existing Bastion profile
    user_auths: ["local_password", "local_sshkey"]
    ssh_public_key: ""                      # empty: no SSH key login on the Bastion
    targets: [windows_common01, linux01_common]   # keys of vms_inventory
    # display_name, email, force_change_pwd

vms_inventory:
  linux01_common:
    name: "Debian01"
    ip: "192.168.1.13"
    service: "SSH"                          # SSH or RDP
    port: 22
    url: "https://linux01.example.com"      # "" for no application

applications:
  rds_server: windows_common01
  rds_account: "svc_appdriver"
  appdriver_path: 'C:\appdriver\appdriver.exe'
  working_dir: 'C:\appdriver'
```

## Things to know

- **An account lists its applications.** The target group attaches the application to the account (`<application>:APP` in its `resources`); the account declares it as well, otherwise every plan would show it as a change to remove.
- **The passwords are in the state** (user passwords, account passwords, RDS account password). Treat the state as a secret; `terraform output -json user_passwords` prints the user passwords.
- **The SSH key credential is generated by the Bastion** (`generate:ED25519`): the private key never leaves it.
